# Codex Review — オンデマンドレビュースキル

## 概要

Claude Code内からOpenAI Codex CLIを呼び出し、コード変更のセカンドオピニオンを得る。

## 前提条件

Codex CLIがインストール済みであること：
```bash
npm install -g @openai/codex
```

環境変数 `OPENAI_API_KEY` が設定済みであること。

## 実行手順

### 1. レビュー対象の特定

ユーザーが指定しない場合、以下の優先順で対象を決定する：

| 状態 | コマンド |
|---|---|
| ステージ済みの変更がある | `git diff --cached` |
| 未コミットの変更がある | `git diff` |
| 直近のコミットをレビュー | `git diff HEAD~1` |
| 特定コミット範囲 | `git diff <base>...<head>` |
| ブランチ全体（main比較） | `git diff main...HEAD` |

### 2. Codexにレビューを依頼

基本パターン：
```bash
git diff HEAD~1 | codex "このdiffをレビューして問題点を指摘して。バグ、セキュリティリスク、パフォーマンス問題、設計上の懸念を重点的に。日本語で回答して。"
```

ブランチ全体のレビュー：
```bash
git diff main...HEAD | codex "このブランチの全変更をレビューして。以下の観点で指摘して：1) バグ・ロジックエラー 2) セキュリティ 3) パフォーマンス 4) コードスタイル・可読性。日本語で回答して。"
```

特定ファイルのみ：
```bash
git diff HEAD~1 -- src/services/ | codex "このサービス層の変更をレビューして問題点を指摘して。日本語で回答して。"
```

### 3. レビュー結果の処理

Codexの出力をClaudeが受け取ったら：
1. 指摘内容を箇条書きで整理してユーザーに提示する
2. 各指摘について「対応すべき」「検討の余地あり」「無視してよい」のトリアージを行う
3. 対応すべき項目があればユーザーに修正するか確認する

## Claudeの行動ルール

1. Codex CLIが未インストールの場合、インストールコマンドを案内して確認を取る
2. diffが大きすぎる場合（500行超）、ファイル単位に分割してレビューを依頼する
3. Codexの指摘とClaudeの見解が異なる場合、両方の視点を提示してユーザーに判断を委ねる
4. レビュー結果は要約して報告し、Codexの生出力はそのまま貼らない
